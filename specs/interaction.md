# 交互组件与键盘状态机

`src/component.ts` 的 `AskAuthorComponent` 是 `ctx.ui.custom` 挂载的那个组件。

## 责任

- 键盘事件路由与状态机：页面循环切换、数字跳转、菜单光标、预览与总览滚动、多选全选、补充说明编辑模式（题目页按题目与选项，总览页针对整卷补充）、`Esc` 二次确认。
- 鼠标路由：作答界面是整屏覆盖层，`handleMouse` 接管 `wheel` 事件并不再让会话记录跟着滚动；作答页按预览区行范围分工（预览区内滚预览内容、其余位置移动选项光标），总览页滚答卷内容，编辑页与推演在途期间吞掉滚轮。
- 鼠标点击：左键按下先把光标移到指针下的菜单项，同一条目上松开才算一次点击并激活它（与空格同义）；题目导航标签在松开时切页；作答页的补充说明按钮在松开时打开该批注的编辑器（题目整体或该选项专属）；底部操作按钮组里点补充说明入口打开题目补充说明编辑器，点确认按钮读现有作答推进；总览页的整卷补充按钮打开编辑器，确认提交按钮提交答卷；编辑页把左键点击换算为编辑框内坐标后转交内置 `Editor` 定位光标；未命中条目、标签、按钮或编辑框的按下与松开不接管，交回 pi 做文本选择。
- 内置 `Editor` 集成：透传 `Focusable` 以定位输入法候选框；无输入框的页面把全角输入法字符收敛为半角，使 `【` / `】` 与全角字母同样命中快捷键。
- 整卷补充：只由总览页写入，与题目批注同族键位（`n` / `N` / `e` 打开，`x` / `Delete` 清空），编辑目标为 `form`，提交后回到总览页。
- 自适应导航：Tab 循环、数字跳转与确认推进沿可见题目序列行走，被条件隐藏的题目直接跳过。
- 推演编排：`confirmAndAdvance` 前发起请求；答案签名未变则复用既有记录，签名变化先 `retractFrom` 再请求；在途期间当前页 Tab 标题与整页内容换成占位，除取消键外忽略输入；只采纳最新请求，中止与卸载一并作废在途请求。
- 缓存：整屏帧按尺寸键与状态突变失效，Tab 栏与菜单项按 `revision` 失效，视图层内容缓存由 `touchDerived` 统一清空。
- 取消与回收：`Esc` / `Ctrl+C` 与宿主 `AbortSignal` 双通道取消；`dispose` 幂等，释放计时器、`AbortSignal` 监听器与缓存池。

## 边界

- 只经模型的读接口判断显隐与选中（`getVisibleQuestionIndices` / `isQuestionVisible` / `isOptionVisible` / `getSelectedIndex` / `getSelectedIndices`），不重算条件。
- 排版全部委托 `view-*`；不直接书写界面文案与几何数值。
- `render` 及其可达函数不写语义状态；滚动位移的归一化只发生在输入路径，透明备忘缓存不在禁止之列。

## 决策

- `dispose` 只设置卸载标记，不用它阻断 `done`：资源已回收但完成回调尚未投递时仍须结算；`finish` 以完成标记保证回调至多投递一次。
- 焦点在题目与选项之间切换时只失效整屏帧缓存，已解析的预览内容保留复用。
- 预览带与选项区的分界只在渲染时确定一次，滚轮路径读取回传的行范围，不重算带序。
- 点击的按下与松开都要求命中同一个目标（标签页索引、菜单项索引、按钮种类或批注编辑目标），避免按下后页面重排导致误激活。
- 确认推进分两条路径：`Enter` / `Ctrl+S` 先把聚焦选项写入模型再推进（选定并确认），底部确认按钮不写入任何选项，只读现有作答，以免覆盖作者先用空格勾好的选择；两条路径在作答未达标时都只在状态栏提示。
- 菜单为空（选项全被条件隐藏）时 `Enter` / `Ctrl+S` 仍然可用，确认只看作答是否达标。
- 提交页的确认提交按钮与 `Enter` / `Ctrl+S` 共用 `submitOrJumpToUnfinished`：作答全部完成才 `finish`，否则跳到第一道未完成的题目并说明原因。
